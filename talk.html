1 · The relational problem

Why one table is not enough

A tabular model needs one row with a fixed number of columns. A customer has 0, 3 or 3000 transactions: a set, not a vector.

Flatten

Aggregate the linked rows into columns (count, mean, max, …). Then use a tabular model.

Can lose: signal further away than the depth limit, and interactions between columns of the linked rows.

Keep the structure

Rows are nodes, key links are edges. Learn on the graph.

Costs: a model per task, or a relational foundation model that must be pretrained on databases.

On the real benchmark, flattening is still competitive.

log: relicl-1, relarena-4

The two losses of flattening are shown by RelICL on synthetic tasks. RelArena shows that flattening plus TabPFN-3 is first among models with standard tuning.

2 · Formal definition

The database

(𝒯, ℒ)

Tables 𝒯 = {T₁, …, Tₙ}

Links ℒ ⊆ 𝒯 × 𝒯. A link (T_fkey, T_pkey) exists if a foreign key column of T_fkey points to the primary key of T_pkey.

A table is a set of rows. A row is called an entity.

v = (pᵥ, 𝒦ᵥ, xᵥ, tᵥ)

pᵥprimary key
𝒦ᵥforeign keys
xᵥattributes; all rows of one table have the same columns
tᵥtimestamp, optional

Notation of Fey et al. 2023, §2.1; the RDL survey uses the same symbols · log: formal-1, formal-2

This is the notation of the relational deep learning position paper. RelBench describes the same objects in words.

2 · Formal definition

The task is one more table

T_train: v = (𝒦ᵥ, tᵥ, yᵥ)

  • 𝒦ᵥ: which entity the example is about
  • tᵥ: when the prediction is made (seed time)
  • yᵥ: the label

The training table has no inputs xᵥ. The input is the database.

To predict yᵥ, use only entities u with tᵤ ≤ tᵥ.

2 · Formal definition

Two ways to learn, and what flattening is

Trained per task

f_θ(x_test, RDB) ≈ y_test

Fit θ on the training table of this task.

In-context

y_test = f_θ(x_test, D_ICL, RDB)

D_ICL = {(xᵢ, yᵢ)} are labelled examples. No training on the task.

Flattening is a fixed function g of the neighbourhood

u = g(N_RDB(x)) z = [x; u] y_test = f_θ(z_test, D_ICL of z)

The database reaches the model only through g.

Notation of RDBLearn §2–3 · log: formal-7

g is not learned. This is the point where a learned or prior-matched flattening would enter.

What RelArena found when it re-ran the methods

  • Two evaluation regimes are in use. On rel-f1 the difference is more than 10 AUC points.
  • A label leak in rel-event/user-ignore was fixed in 2026. Old numbers are 2 to 6 AUC points too high.
  • Tuning effort differs and is often not documented.
  • Each paper aggregates regression results in a different way.

Robinson et al. 2024; Hayler et al. 2026, §1 · log: relbench-6, relarena-2

Regime one freezes the database at the test cutoff for all test rows. Regime two lets each test row see data up to its own timestamp. Only rel-f1 has test timestamps that span years.

4 · TabPFN-Rel

Flatten the database, then predict in-context

Database + training table

Tables, key links, one row per (entity, seed time, label).

Deep feature synthesis

Aggregate along all key paths up to depth d. Each row sees only data before its cutoff.

One flat table

Plus calendar features and past labels of the same entity.

TabPFN-3

Train rows are the context. Test rows are the queries.

  • Prior Labs' harness around TabPFN-3. No relational model is trained.
  • Lineage: featuretools (DFS) → RDBLearn → TabPFN-Rel.

Hayler et al. 2026, §2.2 and code · log: tabpfnrel-1, tabpfnrel-3

In the formal view of slide 6, deep feature synthesis is the fixed function g and TabPFN-3 is f.

4 · TabPFN-Rel

The settings

PartSetting
DFS depth d2, 3 or 4, chosen on validation. The only tuned value.
DFS enginefastdfs, SQL on DuckDB. Computed once at depth 4, cut down for 2 and 3.
Time columnsTurned into "time before the cutoff".
Text columnsDropped. The API version re-attaches the entity table's text.
Added featuressin/cos of month, weekday, day of year; lags of the entity's own past labels.
Context100,000 rows per estimator, drawn from the 400,000 most recent training rows; 8 estimators.
Test timeValidation rows are added to the context.

Against RDBLearn: TabPFN-3 only, 10× more context rows, recency-aware context, text, and a tuning split frozen at the val cutoff.

Paper + relarena code · aggregation list not confirmed yet · log: tabpfnrel-2, tabpfnrel-3

RDBLearn's default aggregations are max, min, mean, count, mode, std. It is not yet confirmed that TabPFN-Rel uses the same list.

4 · TabPFN-Rel

Results on RelArena, and the limits

Results

  • RelArena: 21 RelBench entity tasks, one harness, one evaluation regime, Elo over tasks.
  • TabPFN-Rel is first among methods with the standard tuning regime.
  • First overall is RT-PluRel: a relational transformer pretrained on synthetic databases, then fine-tuned per task.
  • A predictor that returns each entity's own past average beats two GNN methods on 4 tasks each.

Limits the authors state

  • One seed.
  • DFS is CPU work and can take hours per database. It is not in the runtime table.
  • Tuning the depth helps on 9 of 21 tasks only.
  • Without text the Elo drops from 1821 to 1706. Two tasks cause this.
  • Methods do not all use the same timestamp boundary.
  • No gradient-boosted trees on the DFS features yet.

Hayler et al. 2026 · log: relarena-4 to relarena-9

RT-PluRel is a system submission: it runs its own tuning, up to 50,000 fine-tuning steps per task. The two text tasks are rel-event/user-ignore and rel-avito/user-clicks.

5 · Related work

Each method changes a different part

RDB-PFN

Changes the prior, keeps DFS

  • Synthetic databases → DFS → a 6-layer PFN
  • Binary classification only
  • Context up to 1024 rows, 30 columns
  • Tested few-shot, not in the full RelBench protocol
  • Its own ablation: DFS settings move average AUC from 0.57 to 0.73

RelICL

Changes the flattening, keeps the tabular model

  • No training, no depth limit
  • Sees column interactions
  • "On par" with TabPFN-Rel on RelBench, with numbers copied from the papers

PluRel → RT

Changes both: relational model, relational prior

  • Needs fine-tuning per task to be first on RelArena
  • OpenRFM: synthetic-only pretraining leaves RT in a "lazy" regime

log: rdbpfn-1, -4, -6, -7 · relicl-2, -4 · relarena-4 · openrfm-1

RDB-PFN's schema generator is trained on real schemas, so only the table contents are synthetic. Its released config has width 96; the paper says 128.
